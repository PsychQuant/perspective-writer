## Context

perspective-writer 的交付前檢查目前有四關：Phase 5 黑名單（詞彙與套語）、5a natural-voice（作者自審）、5c ensemble 複核（選用）、5d 跨模型潤稿（改寫）。四關都沒有問「這句話的語序是不是產出語言的母語者會寫的」。5a 的依據 `natural-writing-checklist.md` 抄自英文的 Wikipedia field guide，語法一節只含英文現象。

PsychQuant/perspective-writer#17 的實例說明缺口有兩層：規則層沒有這一問；流程層，問題句是在 Phase 6 修改時才加入的，而 Phase 6 沒有規定修改後要重跑任何檢查。

使用者在 #17 的 Clarity Surface 與 spectra-discuss 中已確認：判準是「產出本身所用語言」；讀者是不知道句子來源的獨立讀者，採同家族 subagent；已知句構清單只當起點；規則放 core；calibrate 模式不跑。

## Goals / Non-Goals

**Goals:**

- 每次交付（Compose、Revise、Phase 6 每一輪修改）前，都有一個不知道句子來源的讀者依產出語言的母語語序讀過交付文字。
- 讀者的判讀有一份明寫的起點清單可以對照，清單同時列出不該標的反例。
- 讀者不可用、失敗或逾時時，交付照常進行，並留下一行可見的說明。

**Non-Goals:**

- 不處理 Phase 5／5a／5d 在修改輪不重跑的一般缺口（#19）；本 change 只讓 5e 自己在修改輪重跑，並定義「改動句」供 #19 沿用。
- 不處理術語中英混用（#18）。中文句子裡的英文術語不代表那句是英文，也不構成語序問題。
- 不建立繁體中文以外的起點清單；其他語言的產出照樣執行 5e，只是沒有清單可以對照。
- 不修改任何 facet；facet 日後可以補文類特有的檢查點，但不在本 change。
- 不在 calibrate 模式執行。
- 不同步 codex 版的鏡像（psychquant-codex-plugins），那邊已分岔，屬另一個 repo 的發布流程。
- 否決的做法：放進 5a 作者自審清單（作者看不見自己句構的來源）；寫進 5d 外部模型的 prompt（5d 是改寫者且知道稿件脈絡，不是盲讀者）；外部模型當讀者（每次交付兩次外部呼叫，且修改輪要重跑，成本累積）。

## Decisions

### 新 phase 編號為 5e 並排在 5d 之後

5b 已被輸出格式規範占用（併進 Phase 5）。5e 排在 5d 之後、Phase 6 呈現之前，因為 5d 由外部模型改寫，改寫本身也可能帶進直譯句構；讀者要讀的是使用者實際會看到的那一版。Compose 與 Revise 一律執行，沒有觸發開關，比照 5d（email facet 已寫明 5d 沒有觸發決策可分工）。替代方案「做成像 5c 的選用步驟」被否決：最需要它的時候最容易被跳過。

### 讀者採同家族獨立 subagent

讀者由起草的 agent 以 subagent 派出，與起草者同一模型家族，但不是同一個 agent，也不在起草的對話脈絡裡。使用者在 spectra-discuss 中選定此方案。取捨：同家族可能共享直譯盲點，以明寫的起點清單補；換來的是每輪修改都負擔得起的成本，且不新增外部依賴。同一 session 由起草 agent 自己再讀一遍不算數，理由同 5d 第二層。

### 讀者輸入只給最終文字、語言標記與起點清單

讀者拿到三樣：(1) 要交付的文字，或修改輪時的讀取範圍；(2) 產出語言的標記（例如 zh-Hant）；(3) 該語言的起點清單全文，若存在。讀者不拿草稿、英文或其他語言的來源、Phase 1–3 的聲音模型、收件人脈絡、使用者的指示。理由：讀者一旦知道句子想表達什麼，就會像作者一樣看懂意思而放過怪語序。語言標記由產出本身的主要語言決定，不由收件人所在地決定。

### 讀者只標記不改稿

讀者回傳逐句的標記，每筆包含原句、不順的原因（對到起點清單的哪一條，或寫明「母語語感」）、一個母語的改寫建議；沒有要標的就回傳「無」。起草的 agent 逐筆決定採用或不採用。採用的改寫要通過 5d 的 frozen span 驗證（每個 frozen span 仍存在且出現次數不變），不通過就不採用。Phase 6 呈現時附一行摘要：讀者標了幾句、採用幾句；未採用的逐句列出原句與原因，讓使用者可以推翻。替代方案「讓讀者直接改寫」被否決：那會變成第二個 5d，可能動到事實錨點。

### 降級時照常交付並附一行說明

派不出 subagent、subagent 失敗、逾時或回傳無法解析時，照常交付，並在 Phase 6 呈現時附一行：「（語序檢查未執行：<原因>）」。不重試、不詢問使用者、不阻斷交付，比照 5c／5d 的降級鐵律。

### 修改輪只重讀改動句與前後各一句

Phase 6 每一輪修改後、再次呈現前，執行 5e，但只讀「改動句」加上它們前後各一句。定義：以句末標點（。！？；以及 . ! ? 後接空白）與換行切句；新版本中每一句，若在「上一次呈現給使用者的版本」裡找不到逐字相同的句子，就是改動句。讀取範圍是所有改動句，加上每個改動句在新版本中的前一句與後一句；相鄰範圍合併，不重複讀。第一次呈現沒有上一版，全文都讀。本定義供 #19 沿用。

### calibrate 模式不執行 5e

calibrate 模式的回傳只能是 status header 加校準後的草稿（README 契約 promise 7），而且沒有人可以看讀者的標記。README EXTERNAL-CONSUMER CONTRACT 的「不適用的 core sections」具名列舉加上 *Native-syntax Read*，並寫明排除理由。這是範圍說明，不改變 consumer 已依賴的行為，契約維持 v2。代價明寫在 README：經由 calibrate 產生的草稿不經語序檢查。

### 起點清單不是封閉列舉並附反例

新增 `references/zh-Hant-syntax-checkpoints.md`。檔頭明寫：清單是檢查起點，不是封閉列舉；最終判準是母語寫作者會不會這樣寫。第一條「整個子句當主語，再接『是…的』」附 #17 實例與改寫。反例一節列出使用者判為可接受的四句與一個中文正常話題句，註明讀者不應標出。清單依 `common-spec-prose-enumeration` 的紀律寫出失敗史（#17），避免日後被「總括」掉。

**讀者回傳格式**（寫進 5e 的讀者指示）


## Risks / Trade-offs

- [同家族讀者共享直譯盲點，標不出起草者慣用的句構] → 起點清單把已知句構明寫出來，讀者對照清單而非只靠語感；清單隨實例累積。
- [過度標記：把中文正常的話題句當倒裝] → 反例一節與驗收表；Phase 6 列出未採用的標記，由使用者裁決。
- [讀者的改寫建議本身也是翻譯腔] → 讀者只建議；採用前由起草 agent 判斷，且須通過 frozen span 驗證。
- [修改輪只讀改動句，漏看改動句與未改上下文的銜接] → 讀取範圍含前後各一句。
- [切句規則誤切：引號內的句號、清單項目] → 前後句緩衝；誤切只會多讀或少讀一句，不影響交付。
- [每次交付多一次 subagent 呼叫] → 修改輪只讀改動範圍；降級不重試。
