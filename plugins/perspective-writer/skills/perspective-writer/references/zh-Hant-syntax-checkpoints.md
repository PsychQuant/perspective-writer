# 繁體中文語序檢查點（Phase 5e 讀者用）

**這份清單是檢查的起點，不是封閉列舉。** 最終判準只有一個：一個以繁體中文寫作的母語者，會不會這樣排這句話。不在清單上的句子，讀起來不順照樣要標；在清單上的句型，放在這個句子裡讀起來自然，就不標。

清單的用途是補讀者的盲點。讀者和起草者可能是同一個模型家族，起草時慣用的直譯句構，讀者光靠語感也可能覺得順。把已知的句型寫出來，讀者就有東西可以對照。

## 檢查點

### 1. 整個子句當主語，再接「是…的」

**形狀**：主語位置是一個完整的命題，有自己的主語和動詞；後面接「是可以證明的」「是很清楚的」「是值得注意的」這類只在評價這個命題的謂語。

**來源**：英文的 *That X is provable.* / *It can be shown that X.* 逐字換成中文。

**實例**（#17）：

> 精確的 rank 不會上升是可以證明的，我用 Lean 4 檢查過；

**改寫**：

> 可以證明精確的 rank 不會上升，這點我用 Lean 4 檢查過；

中文通常把評價放在前面（可以證明、我們知道、值得注意的是），或把命題拆成主題加評論。

**不屬於這一條**：主語是名詞短語而不是整句命題時，「是…的」很自然，不標。例如「這個做法是可行的」。

## 反例：以下句子不要標

使用者判定這些句子可以接受。它們有的看起來像英文句構，但都是中文書面語或書信裡正常的寫法。

| 句子 | 為什麼可以接受 |
|---|---|
| 這些定點我只抽查了一部分，抽查到的都不吸引。 | 話題句：先提主題再評論，是中文的基本句式 |
| 所以我想到的是，不必每個維度各追一次階段的路線，而是改用這個共同的形狀。 | 「我想到的是」在書信和口語裡常見 |
| 一般維度真正要補的，是後面三件。 | 「…的，是…」的強調句是中文書面語常見的寫法 |
| 修正後的證明，以及原本那一步的反例，都已經用 Lean 4 檢查過。 | 受事放在主語位置、不帶「被」，是中文正常的結構 |
| 正好會被帶到這些定點上的起點也是例外。 | 前置修飾稍長，但仍在一般讀者讀得順的範圍內 |

## 失敗史

**2026-10-01，#17。** 一封中文學術回信裡出現檢查點 1 的實例，由使用者在寄出前自己讀出來。那一句是在 Phase 6 修改時才加入的，當時沒有任何一關檢查語序；Phase 5a 的清單抄自英文的 field guide，也沒有一項可以對照。這是本清單和 Phase 5e 的起點。

同一封信裡，AI 另外標了四句疑似直譯，也就是上方反例表的後四句，使用者判定「其實還好」。所以這份清單**不能**總括成一條「避免英文句構」之類的判準：那樣寫，讀者會把這四句也標出來。每一條檢查點都要有一個真實的實例，邊界則靠反例劃出來。

## 增補

新增一條檢查點時，附上真實的實例（在哪份產出、由誰讀出來）與改寫。使用者判定可以接受的句子，加進反例表，並寫一句理由。
